# 目的地系统

旅行"去哪里、带回什么"的整套机制。它在客户端里完全不存在（客户端检索 `TravelData` 零命中），
原本只运行在服务端；本项目用归档的服务端表把它复原成表驱动实现。

## 数据

| 表 | 内容 |
|---|---|
| `Area.json` | 17 个区域，每个带 **id 区间**（如 `A_NORTH` = 0–999、`A_BWG_JXS` = 12000–12999）。这个区间同时也是物品效果里 `AREA_DECIDE` / `AREA_STEP` 的取值空间 |
| `Node.json` | 373 个点：`nodeType` `-1`/`0` 普通、`1` = **终点**（34 个，与 `NodeGoal` 一一对应）、`2`/`3` 岔路与特殊路段点；终点带 `picTag`（如 `g_beijing`） |
| `NodeConnect.json` | 邻接表。**边以"一对端点"写在其中一个端点的行上**（例如 `12001 -> [12000, 12001]`），所以可行走邻接要取**两个方向的并集** |
| `NodeEdge.json` | 按"**抵达**该点"1:1 索引（406 行）：耗时 `time`、特殊路段加时 `plusTime`、`wayType`、三类照片标签及权重、遭遇伙伴与概率、最多 3 条笔记 id |
| `NodeGoal.json` | 34 个终点 = 29 个省市 + 5 座博物馆，带 `itemPer` 权重 |
| `NodeItem.json` | 每个点的产出：特产 `specialtyId/specialtyPer`、纪念品 `collection`、装饰 `decorationId/decorationPer`、`drop` |
| `MainData/Item.json` | 181 行 `effects`（客户端自己的 `Item` 表没有这一列），驱动便当/护身符/道具的实际效果 |

生成器：`work/tools/build_travel_data.py` → `work/run/engine/data/travel.json`。

### 判定依据（两条容易读错的语义）

1. **邻接取双向并集**：单向读时 17 个区域只有 10 个能从入口走到终点，且**五座博物馆全是死路**；
   取并集后 **17/17 全部可达**（`work/tools/analyze_traveldata2.py` 可复算）。
2. **`wayType ↔ 工具族`**：`wayType` 1/2/3 的行里，工具标签分别只有 `p_fuza` / `p_wet` / `p_dry`，
   而道具（竹筒/葫芦/水壶、纸伞、睡垫）的 `EVT_WAY` 分别只有 `E_CAVE` / `E_SEA` / `E_MOUNTAIN`
   —— 三处独立印证，不是猜的。

### 照片标签 → 画片

`PictureTag.picNames` 里的名字就是 `Picture.name`，因此
`NodeEdge` 的照片标签 → `PictureTag` → `Picture` 全链条闭合
（65 个路段标签 **65/65** 命中）。终点照另有一条更直接的路径：
`Picture.type == 'Goal'` 且 `place == GoalNumber.id`（五座博物馆是 100–104）。

## 一次行程的算法

```
① 选区域：每个区域基础权重 1；累加携带物的 AREA_DECIDE（该区域 +N）；
          A_NEW_AREA 给"还没去过的区域"加权；博物馆区域仅在携带对应门票时可选
② 走路线：从区域入口出发，每步走到一个相邻点
          抵达耗时 = (time + plusTime) × (1 - WAY_SPEED%)
          进入条件用不含 plusTime 的基础耗时判断，否则特殊路段永远进不去
          wayType 1/2/3 的路段需要对应道具（门票行程例外，见下）
③ 收成：每个抵达点按 NodeEdge 的标签权重掷照片；
        按 NodeItem 的特产权重掷特产；有点位可出纪念品时掷一次典藏；
        收集笔记 id（必须是客户端 Note 表里存在的 id）
④ 终点：首次经过终点记为该趟目的地，并**必定**给一张该目的地的画片
```

预算与换算（属本项目设定，见 `docs/设计取舍与自定数值.md`）：
走行预算 = `Define.TRAVEL_TIME_MIN × 3`，乘以便当 `HP/H_MAXTIME` 的百分比加成；
步数上限 14；终点需在走过 3 步后才算"抵达"。

## 物品效果（`Item.effects`）

| effect | effectType 例 | 含义 |
|---|---|---|
| `HP` | `H_MAXTIME` `H_UP` `H_UP_RND` | 旅行时长（原版 `BASE_HP = 100` 是锚点，取值 6–72 即百分比） |
| `ITEM_PERCENT` | `I_CLOVER` `I_CLOVER_RND` `I_TICKET` `I_UP` | 幸运（额外三叶草/券）与额外特产 |
| `AREA_DECIDE` | `A_NORTH` `A_EAST` `A_NEW_AREA` … | 目的地权重（80 相对基础 1） |
| `AREA_STEP` | 区域名 | 在该区域内多走的百分比 |
| `COST_STEP` | `W_ALL` | 步数折扣 |
| `WAY_SPEED` / `WAY_STEP` | `W_CAVE` `W_SEA` `W_MOUNTAIN` `W_ALL` | 特殊路段提速 / 多走的步数 |
| `EVT_WAY` | `E_CAVE` `E_SEA` `E_MOUNTAIN` `E_NORMAL` | 解锁该族特殊路段 |
| `DETOUR_STEP` | — | 绕路（`Define.DetourMax` 封顶） |
| `FLAG_ITEM` | `FL_RARE` `FL_<省>` `FL_<作物>` | 标记（随特产获得记入存档） |
| `GET_REWARD` | `DROP_ID` | **未实现**：索引一张本仓库没有的服务端掉落表 |

特殊说明：五张博物馆门票（1017–1021）的效果是 `AREA_DECIDE` 且值为 **-2**，无法作为权重解释，
因此按"这张票把行程钉死在这座博物馆"处理，并允许门票行程通过路上的特殊路段
（每座博物馆的路线都含一段，例如江西省博物馆的节点 12007 是一段 `wayType 2`）。

## 彩叶幸运草

物品 1200（商店在售）在服务端表中没有 `effects` 行，其行为只存在于服务端逻辑：
携带它出门时，本趟**第一张照片**用于补齐玩家已有画片组里缺的那张
（分组依据为客户端 `PictureTag`；优先补本趟路过的组）。
