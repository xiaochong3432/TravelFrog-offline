# 3.2 后续修复

本轮针对两条反馈：**「动态照片能点开但不好用：不能制作、添加照片没反应、也不知道显影液怎么获得」**
和**「背景音乐里偶发出现人声/杂音」**。下面每条都给出客户端依据；字符偏移一律相对
`work/run/web/js/main.min.js`（1 265 296 字符）。

## 一、动态照片（`animpicture_*`）

- **加照片完全没有反应**：制作页的 `req_add_pic` 发的是 `animpicture_add_pic`
  （发送点 @80865），回调要求 `0 == e.code` 才会把照片推进 `exp_pic`（@80975）；
  而引擎此前只实现了展示页的 `animpicture_album_add_pic`，这条协议没有处理器 ——
  客户端拿不到回包，照片列表自然不刷新。现在按客户端形状实现：载荷是**相册照片 id 的数组**
  （每条回包带 `code`/`moved`）。
  - 客户端发来的 id **可能已经过期**：它用自己那份内存相册列表把选中的照片翻译成 id，
    重启或引擎侧相册变动之后就会翻出旧 id（真机实测连续三次 `add_pic [45,44,43,42] -> {"code":-1}`）。
    因此空数组或找不到 id 时改用**同款兜底**：只搬运相册里真实存在、且与该页
    `animpictureData.list[页].pic_list` 同款的明信片，不凭空造照片。**同款兜底是【自设计】**，
    取值口径见 [设计取舍与自定数值](设计取舍与自定数值.md)。
  - 拒绝时回包带 `why`（`no-page` / `not-found`），便于再次定位。
- **「不能制作」：`page_num` 从表里算，而不是读存档字段**。客户端制作页的门禁是
  `canShowEmpty() = pic_list.length < data.page_num && phase == 0`（@83316），
  `page_num` 由服务端给；引擎此前一直回存档里的 `page_num`（初值 0），制作页因此永远不出现。
  现在按数据表算：`animpictureData.base_info.album_num`（4）**加上持有「动态相框」(9001) 的个数** ——
  商店里这一行写的正是"获得后动态相册页数+1"（`shopData.json`，itemId 9001，3000 三叶草，限购 1）。
- **显影液用多少瓶都没有变化**：引擎每用一次就推进一层，却既不扣道具也不把新的持有数告诉客户端，
  客户端因此一直显示旧数量；家里早已没货之后仍然让你点，每次只拿到 `{phase:-1}`。
  现在：扣 1 瓶、按显影液推进 **1 / 2 / 3 层**（单色 8002 / 双色 8003 / 多色 8004，
  家具店耗材，价位见 `furnitureShopData.json`）、并用 `item_load_items` 把新持有数推给客户端；
  没有瓶子时明确回 `{phase: -1, why: 'no-item'}`。
  - 逐层推进而不是按 `exp` 折算：`animpictureData` 的每层都有自己的 `exp`，
    但**最后一层的 `exp` 是 0**，任何折算都推不到"完成"（实测 200 瓶多色显影液后页面仍停在第 5 层）。
    `exp` 仍然按客户端模型保留为进度数字，完成时清零。**步数 1/2/3 是【自设计】**，
    依据是三种显影液自己的文案（略有效果 / 真有效果 / 效果显著）。
- **一页做完要真的返还「照片存储开启物」**：客户端在 `phase == 0` 时自己 `item_num++`、
  并把 `exp_pic` 全部收回相册（@83059），随后按 `item_num` 弹奖励卡；引擎此前只把
  `item_num` 记在私有字段里，那张卡就是空头支票。现在 `animpicture_get_item` 把
  `item_num` 个 **9002** 真正放进屋，并把 `item_num` 归零。9002 商店价 500 三叶草、不限购
  （`shopData.json`，itemId 9002）。
- **`animpicture_open_album` 要扣存储券并封顶 4 格**：客户端自己先查背包（数量不足就回
  "物品不足"，连确认框都不给），所以这一格本来就该付费；展示页固定画 **4** 组格子
  ——`AnimPictureShowPage.childrenCreated` 里是 `for(...; 4>o; o++)`（@505700 附近），
  多付的格子玩家根本看不到。
- **九个会改状态的处理器不再推 `animpicture_load`**：客户端的接收端是 `this.data = e`（@79463），
  每步都重推整份模型会把制作页手里那份快照换成新对象，表现就是"有反应但画面没变化"。
  现在这些处理器只回包，界面按回包自己更新。
- **入口 `guide`**：客户端只在 `data.guide > 1` 时显示动态照片入口
  （`animPicBtn.visible` @780792、`guide>1` @780880），而 `guide` 由服务端下发；
  离线没有服务端推它，`guide: 0` 就等于永久隐藏。现在默认 **2**，并在读档时把老存档的
  `guide < 2` 提到 2（**取值 2 是【自设计】**，依据是上面那条 `> 1`；已经进行中的 3/4/5 不动）。

## 二、广告海报的音频

庭院墙上那张海报在 `ChannelType.Test` 下会 `addChild(new AdsVideoView)`
（`AdsVideoView` @464764），而这个类的**构造函数**就 `load("resource/China/video/test.mp4")`
（@464975）；egret 的 HTML5 播放器加载时同时设置 `autoplay` 并立刻调用 `play()`，
元素只有 1×1、甚至没有挂到 DOM 上。外壳此前只拦 `addChild`：既没有阻止 `play()`，
又让播放器永远进不了显示列表（连关闭按钮都没有）。结果是游戏音乐照常，
另有约 52 秒的广告人声/音乐叠在上面 —— 也就是反馈里的"偶发人声/杂音"。

三层修法（都不动 `<audio>`，因此 BGM 与全部音效不受影响）：

1. `installAdsVideoStub()`：`AdsVideoView` 是 `main.min.js` 顶层的 `var`，
   直接把全局类换成惰性替身，构造函数什么都不创建（海报照旧能点，当日奖励照发）；
2. `stopAdMedia()`：万一真有实例漏出来，停掉并释放它已经开始的媒体，并给 `close()`
   换一个无害实现（它原本会在 52 秒后 `this.parent.removeChild(this)` 抛错）；
3. `installSilentVideoGuard()`：兜底守卫，客户端创建的每个 `<video>` 在创建与 `play()` 时静音 ——
   整个客户端只有 `AdsVideoView` 和调试命令 `play_video` 会创建 `<video>`。
