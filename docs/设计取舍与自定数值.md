# 设计取舍与自定数值

照片回收规则：按用户要求，放弃保存的待收照片转入回收站，不直接销毁；相册满导致无法保存时也保留在回收站，恢复仍遵守相册容量限制。

## 2026-09-18 邻居回礼规则补充

堆肥补充：用户将每次发酵暂时缩短为 5 分钟，消耗该格一份特产、累计土地肥力 +1。空闲时从可发酵的非空格随机选一格并锁定，完成后接续下一格；离线按前一次完成时间连续结算。已有 3 小时任务保留开始时间与格位，按新时长结算。沿用客户端选择器允许的特产及庭院肥料类物品，旧档中其他物品仅可取回，不自动销毁。原界面三颗肥力标记分别对应累计 1/2/3 点，超过三点仍累积；按用户要求隐藏肥力数值和剩余时间小字。客户端没有肥力影响生长速率的字段，本次不另造速率公式。

家具补充：按用户要求，全部 `furnitureData.style = 1` 的 27 件素风格家具默认拥有；旧档与导入存档同样补齐，其他风格仍按原有规则解锁。

用户确认困困、胖胖、跳跳应在离开后通过邮件回赠三叶草或一个四叶草。喂食不再将停留截短为 20 秒；原定停留时间不变。奖励领取才入账，旧档已即时发奖的来访不重复补发。

喜好沿用 `Character.taste`，喜好 ≥ 80 使用稀有奖励权重。按本次确认的两类回礼，对 `FRIEND_GIFTPER_NORMAL` / `RARE` 中的 Clover、FourClover 权重重新归一化（普通 80:18，喜欢 20:50）；不再附送兑换券。三叶草数量沿用现有公式及基础奖励，四叶草分支仅给一个四叶草。这是离线版按用户要求调整的规则，不声称恢复官方服务端概率。

原则：**能用客户端数据/代码证明的一律不自造**。下面全部是本项目自行设定的部分，
逐条列出以便复核与调整；引擎中对应位置都有注释标注。

## 一、为可玩性而设的数值

| 项 | 值 | 理由 |
|---|---|---|
| 起始三叶草 | 9999 | 原版靠长期在线积累，离线版需要一次性给足，避免开局卡在种子/食物价格上 |
| 改名费用 | 首次免费，之后 50 三叶草 | 原版收费口径无法从客户端确认，取一个不影响体验的数值 |
| 旅行节奏 | 出门 12–40 分钟、在家 2–6 分钟 | 原版按小时级节奏设计（`Define.TRAVEL_TIME_MIN = 60`），离线版缩短以便一次游玩完整体验；需要原版节奏时可用环境变量 `FROG_FAITHFUL=1` 切回 |
| 邻居喂食后停留 | 保留原定离开时间，到期寄回礼邮件 | 喂食不会再把剩余来访时间截成 20 秒；奖励领取才到账 |
| 手工拼装每阶段 | 90 秒 | 原版由服务端计时，取一个可感知但不必久等的值 |
| 手工品耗材 | 持有制作工具后，每件祈愿物/印章 1 个手工品材料；每块木片 1 个朽木 | 用户确认的规则，工具不消耗；未持有工具时即使播放手工动作，也不扣料、不推进、不产出；不再旅行免费掉落木片 |
| 木片制作 | 270 秒 | 沿用手工每阶段 90 秒，木片按三个阶段时长制作；三种木片等概率，此时长和分配为离线版设定 |
| 友情邀约 | 符合条件的每次来访离开时判定一次，75% | 用户指定概率；持有绘本且喂过好感值 ≥60 的特产，邀请人就是该邻居；已有活动不覆盖 |
| 嘟嘟家具商店 | 按既定停留时间营业，售罄保留列表及“卖完啦”，不提前离开；可重复商品次日按 `shop_limit`（缺省 1）补货，永久限购不重置 | 售罄行为按用户确认规则；原版服务端作息表未取得，使用本地自然日提供可持续补货 |
| 基础肥料箱 | 开局摆放木头堆堆（21000），旧档缺失时补齐 | 客户端有完整箱体和六格存取界面，旧引擎没有发放途径导致入口不可见 |
| 出行准备 | 背包或桌子上必须有便当，回家自动解锁行李 | 按试玩反馈调整；无食物不再触发新放浪旅行，旧旅行存档仍可结算 |
| 三个节日活动 | 常开 | 同上；原版按真实日期开关 |
| 广告 / 分享 / 充值 | 直接发奖 / 直接发奖 / 免费发放 | 离线版不含广告与支付，界面中已明确说明 |
| 界面元素 | 「重载界面」按钮、提示文案、悬浮球的颜色与位置 | 属于本项目新增的辅助界面 |

## 二、目的地系统的换算口径

数据本身是原版的，但下列"单位换算"由本项目确定：

| 项 | 口径 |
|---|---|
| 走行预算 | `Define.TRAVEL_TIME_MIN × 3`（边耗时单位是分钟，跨一个区域约需 150–300 分钟；取 1 倍时一趟只走两步，整张边表失去意义） |
| 食物 `HP/H_MAXTIME`、`H_UP` | 按百分比加到旅行时长（原版 `BASE_HP = 100` 作为锚点） |
| `WAY_SPEED` | 该族路段耗时按百分比下降 |
| `WAY_STEP` | 视为"额外步数" |
| `COST_STEP` / `AREA_STEP` | 按百分比增减步数上限 |
| `ITEM_PERCENT`（`I_CLOVER`/`I_CLOVER_RND`/`I_TICKET`） | 视为"多一件的概率"；抽奖券基础概率沿用离线版原有的 45%，每种效果再加 10 点 |
| `ITEM_PERCENT`（`I_UP`） | 每 50 点折算一次额外特产 |
| 步数上限 / 终点判定 | 14 步；走过 3 步之后经过终点才算"抵达"（部分区域的终点紧邻入口，否则一趟只有一步） |
| 门票 `AREA_DECIDE = -2` | 无法作为权重解释，取"该票把行程钉死在这座博物馆"；门票行程可免费通过特殊路段 |
| 门票来源 | 许愿池（每座博物馆 3 张）。原版由"博物馆冒险"发放，而该玩法默认关闭 |
| 彩叶幸运草补缺图 | 携带时本趟第一张照片用于补齐已有画片组中缺失的一张，优先补本趟路过的组 |

## 四、明确未做的部分

| 项 | 原因 |
|---|---|
| 服务端掉落表相关（`GET_REWARD / DROP_ID`、节点 `drop`） | 该表不在客户端的 60 张表中，也未在 CDN 归档中出现 |
| 堆肥"肥力 → 生长速度" | `compostData` 只有 5 档外观，没有任何速率字段，需要完全自造数值 |
| 旅行中的伙伴遭遇表现（`FRIENDSHIP` / `TRAVELER_STEP`） | 归访客与任务系统；地图节点的"遭遇伙伴 + 概率"字段已解出但未接入玩法 |
| 明信片"中间横带"官方摆位 | 规律无法从数据推出，保持数据表自身坐标 |
| 手绘中国地图 | 公开发布的地图需使用标准地图并标注审图号 |

## 五、可调整的入口

多数数值可通过环境变量覆盖，便于按需回调原版节奏或调整难度：

| 变量 | 作用 |
|---|---|
| `FROG_FAITHFUL=1` | 使用原版调参表中的原始节奏 |
| `FROG_TRAVEL_MIN` / `FROG_TRAVEL_MAX` | 出门时长范围（秒） |
| `FROG_TRAVEL_STEPS` / `FROG_TRAVEL_GOAL_STEPS` | 步数上限 / 终点判定步数 |
| `FROG_TRAVEL_MINUTES` | 走行预算倍数 |
| `FROG_GUEST_ROLL` / `FROG_GUEST_CHANCE` | 邻居串门节奏 |
| `FROG_VISITOR_ROLL` / `FROG_VISITOR_CHANCE` / `FROG_VISITOR_STAY` / `FROG_VISITOR_COOL` | 访客节奏 |
| `FROG_LOTTERY_ROLL` / `FROG_LOTTERY_CHANCE` | 抽奖节奏 |
| `FROG_DRAWING_TRIP` 等 | 绘制/绘本节奏 |

## 六、动态照片（显影液与页数）

客户端只给"一层一层做"的流程，没有给出每瓶显影液的当量、入口何时出现，
也没有给出离线时这些东西从哪来，因此下面三条由本项目设定：

| 项 | 值 | 依据 / 理由 |
|---|---|---|
| 每次显影推进层数 | 单色 1 / 双色 2 / 多色 3 | 三种显影液自己的文案是"略有效果 / 真有效果 / 效果显著"，价位也按 500 / 1000 / 1500 三叶草分档；数据表每层虽有 `exp`，但**最后一层的 `exp` 是 0**，按 `exp` 折算永远做不完（实测 200 瓶多色显影液后页面仍停在第 5 层） |
| 动态照片入口 `guide` | 默认 2；老存档 `guide < 2` 读到 2 | 客户端只在 `data.guide > 1` 时显示入口（`animPicBtn.visible`），而 `guide` 由服务端下发；离线没有服务端推它，`0` 等于永久隐藏。已经进行中的 3/4/5 不动 |
| 「加照片」的 id 对不上时 | 同款兜底 | 客户端用自己那份内存相册列表翻译 id，重启后会发出过期 id（真机实测 `add_pic [45,44,43,42] -> {"code":-1}`）。兜底只搬运相册里真实存在、且与该页 `pic_list` 同款的明信片，不凭空生成照片 |

其余相关数值都取自客户端或数据表，不属于自定：每页 4 格（展示页
`for(...; 4>o; o++)`）、制作页最多 5 张（`exp_pic.length>=5` 时禁用「加照片」）、
「照片存储开启物」9002 每开一格 1 个、商店 500 三叶草不限购（`shopData.json`）、
「动态相框」9001 售价 3000、限购 1、每持有一个动态相册页数 +1。
