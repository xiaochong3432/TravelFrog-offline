## 第 4 层：真页面探针（headless Edge）

```bash
cd work/run/web && python -m http.server 8231        # 另开终端
node work/tools/cdp_drive.js --url http://127.0.0.1:8231/index.html --fresh `
  --wait 9000 --settle 3000 `
  --step in:work/tools/probe_travel_map.js `
  --step log --step shot:shot.png
```

`cdp_drive.js` 的分步指令：

| 指令 | 作用 |
|---|---|
| `eval:<js>` / `in:<file>` | 在页面里求值（`in:` 适合放探针文件） |
| `tap:x,y` | 真实鼠标按下+抬起 |
| `wait:ms` / `shot:<file>` | 等待 / 截图 |
| `log` | 打印 `window.__probeLog` |

要点：

- 退出码非 0 表示页面抛了未捕获异常；结束时看 SUMMARY 的 `exceptions` / `page errors`；
- `in:` 的返回值不会被打印，探针应把结果 `window.__probeLog.push(...)` 后再 `--step log`；
- 同一会话里"找节点 → 点它 → 截图 → 再读状态"才有意义，所以步骤是**按顺序**执行的；
- 用临时 profile（默认 `work/shots/edge-profile`，可 `--fresh` 重置）避免污染真实存档。

工作台连续放料：运行 `work/probe/feedback_bench_slot_refresh.js`。在同一次工作台会话中把两种材料依次放入两个格子；第一格完成后，库存必须立即扣减、第二格列表不得残留已耗尽材料，并且第二种材料无需关闭页面即可放入。引擎测试同时检查放入与取出都会推送 `item_update`。

照片回收：在独立测试档运行 `work/probe/feedback_photo_recycle.js`，从收信窗口关闭并确认放弃，再打开回收站选图恢复；确认对话框正常关闭、照片回到相册且重载后仍保留。引擎另覆盖来访照片、相册满、重复请求及同模板不同照片的编号隔离。

购买三叶草布局：运行 `work/probe/feedback_recharge_layout.js`，确认打开的是 `RechargeSimpleView`，6 个 85px 商品行均位于滚动内容中，页面不溢出固定窗口；点击第一档后引擎三叶草增加 400。

1. 改引擎 → 跑第 1 层 → 重建内联引擎 → 跑第 2 层；
2. 出包 → 跑第 3 层（含 `apk_identity.py`）；
3. 涉及界面/交互的改动 → 跑第 4 层并留截图；
4. 任何"改完必须同时更新"的位置：玩家说明书（`dist/说明书.txt`）、
   `docs/设计取舍与自定数值.md`、以及本仓库的文件清单。
