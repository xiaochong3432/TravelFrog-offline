# 安卓打包接口规范（3.2）

本规范依据维护者提供的《技术说明》和《存档格式-V3.1》，并以实际发布包、当前页面调用和源码核对结果修正旧文档中的版本、端口与路径。适用于 `com.frog.offline` 的 3.2（`versionCode=6`），构建方法见 [构建与打包](构建与打包.md)。

## 发布身份与存档来源

| 项目 | 当前约定 |
|---|---|
| 包名 | `com.frog.offline` |
| 签名 | 沿用旧版证书与私钥，证书 SHA-256 由 `work/release.json` 固定 |
| WebView 加载地址 | `http://127.0.0.1:18763/index.html` |
| 主档键 | `localStorage['frog.offline.save']` |
| 原生镜像 | 应用私有目录中的 `save-mirror.json` |
| 输出 | `dist/TravelFrog-offline-3.2.apk` |

`localStorage` 按协议、主机、端口隔离。补充技术说明中有一处要求使用 `18080`，但实际 3.1 包和《存档格式-V3.1》均使用 `18763`，所以本版继续固定 `18763`。端口不可用时不得静默改成随机端口或直接换到 `18080`。

本次不引入跨源迁移：覆盖升级继续读取同一来源的原存档。今后确需变更来源，必须先实现并验证迁移，只在新来源没有健康存档时恢复，不能覆盖已有进度。`com.travelfrog.offline` 是另一应用，跨包自动搬档不在本次范围内，需玩家在旧版导出、在新版导入。

## JS 与 Java 桥

页面 `work/run/web/__probe.js` 和内联引擎生成器 `work/tools/bundle_engine.py` 使用 `window.FrogNative`。`MainActivity` 必须以这个准确名称注册接口，方法必须带 `@JavascriptInterface`，打开系统窗口、操作 Activity 等 UI 工作须回到 UI 线程。同时保留旧 `SaveBridge` 注册名与已有接口，供旧页面兼容。

| 页面调用 | Java 参数 / 返回 | 约定 |
|---|---|---|
| `FrogNative.platform()` | 无参数，返回 `String` | 返回 `android`，供页面识别宿主 |
| `FrogNative.exportSave(name, json)` | 两个 `String`，返回 `String` | 第一个参数是文件名，第二个是完整 JSON 文本；不能颠倒 |
| `FrogNative.exitApp()` | 无参数，返回 `void` | 退出 Activity 并移除最近任务中的应用卡片 |
| `FrogNative.mirrorSave(json)` | `String`，返回 `void` | 写入应用私有镜像，失败不得中断游戏 |
| `FrogNative.readMirrorSave()` | 无参数，返回 `String` 或 `null` | 返回完整镜像文本；没有镜像时返回 `null` |

导出返回值是接口的一部分：

| 返回值 | 含义与页面处理 |
|---|---|
| 非空位置字符串 | 文件已经写入；显示实际保存位置与实际文件名 |
| `PICKER` | 已打开系统保存窗口，尚未完成导出；等回调确认 |
| 空字符串 | 导出没有完成；不得显示成功 |

Android 10 及以上通过 `MediaStore.Downloads` 写到 Download，成功后读取系统实际使用的名称，避免同名文件导致提示位置错误。较旧系统使用 `ACTION_CREATE_DOCUMENT`；系统回调完成后调用页面的 `window.__saveExported(where)` 或 `window.__saveExportFailed(reason)`。取消操作同样不能报告成功。

页面的存档导入使用 `<input type="file">`，外壳必须实现 `WebChromeClient.onShowFileChooser` 并正确回传选择结果。PC 浏览器的 Blob 下载降级不能用作 Android 导出验收依据：缺桥时 WebView 可能丢弃下载，页面却仍显示成功。

## 存档与镜像边界

主档是 UTF-8 JSON 对象，导出文件就是主档文本，没有新增外层包装、加密或校验字段。应用版本升到 3.2 不表示存档格式版本升级，`saveVersion` 仍由引擎决定；不能把它改成应用版本号。

主档键仍为 `frog.offline.save`，安全副本使用 `frog.offline.save::save.json.bak`、`::save.json.tmp` 和 `::save.json.corrupt-<时间戳>`。导入或编辑后需重新加载，使引擎读取新文本；存档修改工具应保留一份独立备份并验证写后读回结果，不能用引擎自己的备份槽代替长期备份。

原生镜像使用 Android `AtomicFile` 原子写入，非法 JSON 不得覆盖镜像；临时文件和恢复文件由平台管理，不约定固定的 `.tmp` 文件名。读档时优先采用健康主档及可用安全副本，镜像只作恢复来源，不能覆盖健康主档。存档状态应能区分正常加载与镜像恢复。

**镜像不是应用外备份。** 它可以在 WebView 存储缺失而应用私有文件仍在时提供恢复来源，但清应用数据或卸载会连镜像一起删除。补充技术说明将镜像列为清应用数据后的兜底，这一点不适用于应用私有目录；需要保留这类操作后的数据，必须先导出并确认文件可读。

## 构建与发布验收

正式入口 `work/tools/build_release_apk.py` 从当前 Java 源码编译 DEX，沿用实际旧包的 Manifest 结构、图标与资源表，仅更新 Manifest 版本字段。不能继续逐字节沿用缺少 `FrogNative` 的 3.1 DEX，否则网页修复无法接通原生接口。游戏资产必须与当前本地运行时一致，签名与应用身份必须与升级基准一致。

每次发布至少完成以下验收，并在发布记录中区分静态检查和设备实测：

1. 核对包名、签名、版本递增、固定加载地址和存档键；校验游戏资产、DEX 和资源对齐。
2. 在已有存档的应用上执行 `adb install -r`，保留升级前备份；启动后核对身份、库存、旅行和相册，再重启一次检查持久化。
3. 在 WebView 内确认上述 `FrogNative` 方法及旧 `SaveBridge.saveFile(text, name)` 存在；在游戏菜单导出，检查真实文件存在、JSON 可解析且与导出时的存档内容一致。
4. 检查导入能打开系统文件选择器并载入已备份存档；检查退出游戏实际关闭应用。SAF 路径需覆盖保存成功与取消。
5. 仅在独立测试存档上验证镜像：确认已写出镜像后，让 WebView 主档与安全副本不可用，重启检查恢复来源与内容；另确认健康主档不被旧镜像覆盖。不能通过清应用数据来模拟这一步。
6. 打开旧相册照片，按 [照片图层验收方法](照片图层修订.md) 检查画面、顺序和尺寸。

APK 中检索到接口名、引擎测试通过或浏览器导出成功，都不能代替上述 Android 设备实测。本页列出验收要求，不表示每个系统版本已经验收。
