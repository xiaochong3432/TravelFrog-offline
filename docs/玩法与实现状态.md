# 玩法与实现状态

本项目的判定标准是**客户端自身的行为**：所有协议以客户端 `main.min.js` 里的真实发送点/回调为准，
数值优先取客户端自带的数据表；客户端没有依据的，才由本项目设定并在
`docs/设计取舍与自定数值.md` 中逐条标注。

## 已实现的玩法

### 开局与引导
- 新号起名（首次免费，之后改名消耗三叶草）
- 七步新手引导（起名 → 采三叶草 → 进屋 → 商店 → 背包 → 领奖 → 完成），引导步进**只前进不回退**
- 起始三叶草、每日奖励、幸运日

### 庭院 / 家
- 三叶草田：种植、收获、枯萎与重生、四叶草概率
- 花盆：种植、按品种收获、插花；花卉保留颜色变种，果蔬进入特产图鉴
- 堆肥箱：六格存取，随机选有特产的格位发酵并锁定；暂时每 5 分钟消耗一份、累计土地肥力 +1，再继续下一格。支持离线连续结算，隐藏肥力和剩余时间小字，保留原有肥力图标；已有真实发酵任务保留格位和已过时间，按 5 分钟结算，旧档假发酵索引从新周期开始
- 家具：商店购买、摆放/替换/收纳、墙面地面等装饰、长凳摆件、垃圾桶回收
- 全部 27 件“素风格”默认解锁；旧档及导入存档补齐缺项，保留其他家具与当前摆放
- 工作台：图纸 → 家具；三拼玩法使用三种木片各一块合成木制护符。工作台保持打开时，每次放入或取出材料都会立即刷新库存，切换到其他格子可直接继续放置
- 手工品：祈愿物、印章（含日期与印章状态）
- 手工品制作工具是制作前提，也是小仓库“手工品”入口的显示条件。未持有工具时可以播放手工动作，但不会开工、扣料、推进旧任务或产生成品；工具本身不消耗
- 青蛙回家时收起桌面已完成的手工品，保留收藏记录；重启或再次出门不会重新摆出旧成品，新完成的手工品仍会正常显示
- 每件祈愿物或印章开工消耗 1 个手工品材料；每块三拼木片消耗 1 个朽木，在家制作 270 秒后入库，不再旅行免费掉落。缺料不开工，阶段推进、重启、完成领取均不重复扣料；旧档未完成的免费制作需先补齐材料，已完成记录不追扣
- 完成通知携带完整手工品记录，桌面图标与点击后的图片、日期均正常显示，兼容旧档中已完成的手工品
- 帽子：仅青蛙离家或照镜子时隐藏；睡觉时保留
- 蜡烛：青蛙在家且清醒时点亮，不受白天/夜晚限制
- 庭院随昼夜与天气推送刷新；收花保持当前镜头位置
- 小组件 → 拍照 → 右侧“抓拍”：切换局部取景，拖动取景框，选择小/中/大尺寸后按框内快门；命中未收集的动作或彩蛋时解锁回忆。普通全景/屏幕拍照不触发抓拍判定

### 旅行（含目的地系统）
- 出门/回家由引擎自行调度；背包或桌子的食物栏必须有便当才能出门，回家后行李自动解锁
- **目的地由道具与食物决定**：护身符/便当的 `AREA_DECIDE` 权重选区域，沿原始地图邻接行走，抵达终点
- 带回：明信片、特产、纪念品（典藏）、花、旅行笔记、三叶草与抽奖券
- 特殊路线：洞穴 / 海 / 山（需对应道具）
- 博物馆：凭门票直达指定博物馆，必定带回该馆目的地照
- 动态照片（多张合成 GIF）：入口 `guide`、页数、加照片、显影液与存储券见下节
- 绘制

### 相册 / 图鉴 / 百科
- 相册：351 张明信片、分页、删除到回收站、恢复、分享、扩容（容量按张数计算）
- 收信时放弃保存的照片移入回收站，普通与来访照片均保留原编号和内容，可恢复到相册；相册满导致无法保存时同样保留，重复操作不会重复入站
- 同模板旅行照片允许再次寄回，每张分配独立编号
- 返程推送待收取照片；登录补发旧档积压的普通照片，进入原客户端收信/保存流程
- 照片保存：浏览器下载 PNG；新原生外壳支持 Android 10+ 写入相册，旧系统通过系统文件选择器保存（原生接口已编译，设备保存待验收）
- 图鉴：纪念品（典藏）62 种、特产 64 种、博物馆藏品
- 购买三叶草：使用客户端自带的紧凑滚动列表显示全部 6 个档位，避免田地促销页的固定列表溢出窗口；离线点击直接到账
- 百科：23 个物种，分「花草/果蔬/木本/其他」四页，含品种、分类/习性/产地/花语
- 明信片「地图」= 省区足迹页（自制页面，见自定数值文档）

### 动态照片（会动的明信片）
- 入口由引擎给出：`guide` 默认 2（客户端只在 `data.guide > 1` 时显示），老存档读档时补到 2
- 页数 = `animpictureData.base_info.album_num`（4）+ 持有「动态相框」(9001) 的个数，制作页因此有入口
- 制作页「加照片」= `animpicture_add_pic`（相册照片 id 的**数组**），id 过期时用同款明信片兜底
- 显影液：单色/双色/多色每次推进 1/2/3 层，扣道具后把持有数推给客户端；没瓶子明确回 `phase:-1`
- 存储券：开一格扣 1 个「照片存储开启物」(9002)、封顶 4 格；一页完成时奖励卡上的券真正入屋
- 改状态的处理器**不再推** `animpicture_load`（客户端收到就 `this.data = e`，会把制作页的快照换掉）

### 访客与邻居
- 33 个省区的小青蛙串门、省花插画、喂特产、回礼、地毯
- 邻居小伙伴：喂食、愿望、许愿池；困困/胖胖/跳跳喂特产后保留原定来访时长，离开时寄回礼邮件，领取后到账
- 友情绘本（绘制）：持有绘本时，院子邻居吃过喜欢或非常喜欢的特产（好感值 ≥60），按原定时间离开时以 75% 概率留下自己的邀约，同时正常寄送回礼邮件。每次来访只判定一次，已有邀约或进行中的聚会不覆盖，不再定时随机生成；离线离开也会结算

### 商店与活动
- 商店：食物、护身符、道具、套装（工具/材料礼包**购买即拆包**）
- 嘟嘟家具商店：售罄商品保留并显示“卖完啦”，全部售罄也按原定停留时间离开；次日补充可重复商品，永久限购商品不重置
- 抽奖（`Prize` 表 + 原版权重）、扭蛋胶囊、料理、故事、便利贴
- 活动：博物馆图鉴、手工拼装、生日蛋糕、春节贺卡、祝福贺卡、年度回顾、分享奖励
- 日历：按真实系统日期显示，含新手 7 天奖励、每日任务、幸运日

### 邮件 / 礼品盒 / 任务
- 邮箱：收信、领附件、广告信（离线版免看视频直接给）
- 窄屏庭院默认镜头靠右，让实体信箱避开右侧活动按钮；新手/邀请引导仍可临时隐藏信箱
- 礼品盒：赠送明信片/特产、分享码往来
- 「伴蛙前行」任务面板：日常任务与累积计划奖励（`taskData` 的 `list_type` 分档领取）
- 称号选择持久化；解锁新成就不自动替换已选称号，保留红点提醒

### 存档
- 单存档文件 + 槽位；写入后**回读校验**；`save.json.bak` / `.tmp` / 损坏隔离 `.corrupt-<时间戳>`
- 悬浮球内提供存档导出/导入与「存档状态」面板
- **旧存档兼容**：新增字段一律可选，缺失时惰性生成

## 明确未实现 / 无法实现

| 项 | 原因 |
|---|---|
| 物品 `GET_REWARD / DROP_ID` 与地图节点的 `drop` | 两者指向同一张**服务端掉落表**，客户端的 60 张表里没有 |
| 伙伴 `FRIENDSHIP / TRAVELER_STEP` 的旅行内表现 | 归访客与「伴蛙前行」系统处理；地图节点上的"遭遇伙伴 + 概率"字段已解出但未接入玩法 |
| 堆肥箱"肥力 → 生长速度" | 客户端表中没有任何速率字段，需完全自造数值 |
| 7 张明信片 | 客户端数据表本身就是空图层（2033/2035/2039/2040/2041/2042/2075） |
| 明信片"中间横带"（天/海/花/远山）的官方摆位 | 官方摆位规律无法从数据推出，仍按数据表坐标绘制 |
| 手绘中国地图 | 公开发布的地图须用标准地图并标注审图号，故以省区卡片式足迹页替代 |
| 排行榜 | 客户端自身隐藏了入口 |
| 探秘东山岛 | 该增量内容未并入 |
| 博物馆"大冒险"玩法 | 默认关闭，改为开局解锁全部博物馆图鉴（可在引擎中重新开启） |
