# 构建与打包

## 环境

| 需要 | 用途 |
|---|---|
| Node.js 18+ | 引擎单测、CDP 驱动、部分打包脚本 |
| Python 3.8+ | 数据解密、打包、验收脚本 |
| Edge 或 Chrome | `tools/cdp_drive.js` 等用无头浏览器驱动真页面 |
| 静态服务器 | 打开游戏页面（浏览器禁止 `file://` 读本地文件），`python -m http.server` 即可 |
| JDK 17 + Android build-tools | **仅**重新出 APK 时需要（`zipalign`、`apksigner`、`d8`、`aapt2`） |
| Windows + .NET Framework | **仅**编译 PC 启动器 `旅行青蛙.exe` 时需要（其余启动器跨平台） |

## 可移植性（换机器 / 换系统）

**脚本不写死任何绝对路径**：Python 脚本在文件头用
`PROJECT_ROOT = Path(__file__).resolve().parents[2]` 定位仓库根，Node 脚本用
`require('path').resolve(__dirname, '..', '..')`，PowerShell 用 `$PSScriptRoot`，
引擎本身用 `__dirname`。因此整个仓库搬到任何目录（Windows / Linux / macOS）都能直接跑。

需要外部工具链的脚本会在缺东西时**打印怎么指给它**，支持以下环境变量：

| 变量 | 作用 |
|---|---|
| `JAVA_HOME` / `FROG_JAVA_HOME` | JDK（`javac`、`java`） |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | Android SDK 根；`build-tools/*` 与 `platforms/*/android.jar` 从它下面找 |
| `FROG_ANDROID_BUILD_TOOLS` | 直接指定含 `aapt2`/`d8`/`zipalign`/`apksigner.jar` 的目录 |
| `FROG_ANDROID_JAR` | 直接指定 `android.jar` |
| `FROG_BROWSER` | 无头浏览器可执行文件（默认按各系统常见位置与 PATH 查找 Edge/Chrome） |
| `FROG_CSC` | 编译 PC 启动器用的 `csc.exe`（非 Windows 不支持） |

也可以在仓库默认位置放工具链（这些目录不入库）：`work/jdk/`、`work/bt/android-*/`、`work/plat/*/android.jar`。

## 构建链

```powershell
# ① 重建"内联引擎"——改了引擎或数据表之后必须执行，否则页面里跑的还是旧代码
python work\tools\bundle_engine.py
#   产出 work/run/web/__offline-engine.js
#   它把 engine/index.js、protocol.js 与 gamedata/define/picture-layers/travel 四张表
#   一起内联，并注入 fs / process 桩。新增数据文件时记得同步它的内联清单，
#   否则 require 会在 try/catch 里静默降级。

# ② 若客户端资源缺失（首次 clone 或最小仓库），先从自有安装包重建
python work\tools\extract_game.py     # base.apk 的 assets/game/ -> work/run/web
python work\tools\patch_game.py       # 幂等离线补丁（从 main.min.js.clean 出发）

# ③ PC 解压即玩包
python work\tools\build_pc_exe.py     # 编译 C# 启动器（源码 work/app/pc/FrogLauncher.cs）
python work\tools\build_pc_zip.py     # -> dist/TravelFrog-PC.zip

# ④ 安卓包
python work\tools\build_wrapper_apk.py
#   产出 work/build/wrapper/TravelFrog-wrapper-unsigned.apk
#   内容只有 AndroidManifest.xml / resources.arsc / res / classes.dex / assets/game/**
python work\tools\sign_apk.py --in work\build\wrapper\TravelFrog-wrapper-unsigned.apk `
                             --out dist\TravelFrog-offline.apk
python work\tools\apk_identity.py     # 必须 RESULT: OK
```

### PC 包内的布局

```
TravelFrog-PC/
  旅行青蛙.exe        .NET 启动器（无需 Python / 无需改执行策略）
  play_frog.bat       回退入口（有 Python 用 Python，否则 PowerShell）
  play_frog.py        Python 启动器
  play-pc.ps1         无依赖的 PowerShell 启动器（HttpListener）
  说明-先看这个.txt    玩家说明书（= dist/说明书.txt）
  web/                游戏本体（index.html + js + resource + 内联引擎）
```

### 安卓外壳

`build_wrapper_apk.py` 生成的是一个**干净外壳**：不包含原包的渠道 SDK、推送、广告、
安全组件与原生库。它只做两件事：

- `AssetServer`：把 `assets/game/**` 通过本地回环 HTTP 提供给 WebView（只读）；
- `MainActivity`：WebView 容器 + 存档导出/导入桥（`SaveBridge`）。

> **不要**用 `tools/build_apk.py`：它会重新打包原始 APK，保留原 Application 类与渠道组件，
> 结果是装机后卡在渠道"登录中"界面。`tools/apk_identity.py` 专门检查这一点。

### 签名

必须使用官方 `zipalign` + `apksigner`（v1 + v2）。历史上自写的签名器漏写了 v2 签名块
尾部的 16 字节 magic，导致真机提示"安装包似乎无效（缺乏开发者证书）"。
后续版本**必须沿用同一把密钥**，否则 Android 会要求先卸载旧版（存档随之丢失）。

## 启动器的端口策略

浏览器按"地址"隔离 `localStorage`，端口一变就等于换了存档位置。四个启动器共用同一套策略：

1. 8080 空闲 → 使用它，并把端口记到 `last-port.txt`；
2. 8080 上已经是自己的服务 → 直接复用该地址，不另开服务；
3. 8080 被别的程序占用 → **停下来提示**（附 `netstat -ano | findstr :8080`），
   要换端口必须显式加 `--allow-other-port`（PowerShell 版为 `-AllowOtherPort`）；
4. 上次用过的端口仍空闲 → 沿用它。

验收：`python work/tools/test_port_policy.py`（11 项）与
`pwsh work/tools/test_launcher_port.ps1`（28 项）。

## 工作区之外的补充

- 客户端原始资源（`work/run/web/resource/`，约 260 MB）默认不入库，用 `tools/extract_game.py` 从自有安装包重建；
- 需要一份自带资源的完整副本时：`python work/tools/stage_repo.py --with-assets`
  （把脚本所在工作区整理成可直接 `git init` 的目录；不加参数则是不含资源的精简版）。

## 发行注意事项

- APK 与压缩包体积较大（200 MB 级），建议通过 Releases 或 Git LFS 分发，不要直接进仓库；
- 发布前跑完 `docs/测试与验收.md` 里的四层验收，尤其是 `apk_identity.py`；
- 玩家说明书（`dist/说明书.txt`）与包内 `说明-先看这个.txt` 是同一份，改动后重新打包即可同步。
