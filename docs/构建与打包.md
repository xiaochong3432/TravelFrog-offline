# 构建与打包

## 升级与存档规范（3.4）

**3.4 沿用 3.1 恢复的原发布路线 `com.frog.offline`。**
原签名保存在仓库 `dist/offline-signing-key.pk8` 与 `dist/offline-signing-cert.pem`，已与本地原版 `com.frog.offline` APK 核对一致。
构建从 `work/app/src/com/frog/offline/` 编译 `MainActivity.java` 和 `AssetServer.java`，生成新的 `classes.dex`，补齐页面使用的 `FrogNative` 桥，同时保留旧 `SaveBridge` 接口。
目标旧包的资源表、图标和其他 `res/` 文件逐字节保留，Manifest 只改版本字段，游戏文件替换为当前 `assets/game/`。HTTP 地址和存档键保持不变。
构建仍需合法持有的实际旧 APK 作为资源与升级身份基准；原包和成品二进制均不提交入库。桥的方法签名、返回值及存档边界见 [安卓打包接口规范](安卓打包接口规范.md)。

另一个 V3 实包的检测结果如下，供区分升级路线。它**不能**直接升级为本次 `com.frog.offline`，也不能凭它推断 V1/V2 的身份。

| V3 实包检测项 | 结果 |
|---|---|
| 包名 | `com.travelfrog.offline` |
| 版本 | `versionName=1.0.0-offline`，`versionCode=1`（文件名中的 V3 是发布名称） |
| APK SHA-256 | `2b5c2cbcad76c84df475e06b4ddaba57a0c09d9b977d24c84a2680d6d8437b19` |
| 签名证书 SHA-256 | `dbd2ac1b09ebef068ff18612004556e69c74cdc578fdfdc74595bac25e448efc` |
| WebView 地址 / 存储键 | `file:///android_asset/index.html` / `frog.offline.save` |

原路线签名证书 SHA-256 为 `b173b2890e9428b2bcfcb576c1f59d4b5ac6c8da887aeda054ebb72b838bf5b3`，与上表不同。正式版本定义见 `work/release.json`。

| 字段 | 3.4 要求 |
|---|---|
| Android 应用包名（`applicationId`） | **`com.frog.offline`，保持原路线** |
| `versionName` / `versionCode` | `3.4` / `8`；覆盖升级的 `versionCode` 必须大于目标旧版 |
| APK 文件名 | `TravelFrog-offline-3.4.apk`；文件名改动不影响存档 |
| 签名 | 与目标旧版相同的证书和私钥；不得临时生成新密钥 |
| WebView 地址 / 存储键 | 保持 `http://127.0.0.1:18763/index.html` / `frog.offline.save` |

Android 按应用包名隔离数据：换 `applicationId` 会安装成另一个应用，原存档仍在旧应用中但新应用读不到。
签名不匹配会拒绝覆盖升级；**不能通过先卸载旧版解决**，卸载会删除应用数据。
即使包名和签名不变，改用另一种 WebView 地址（例如更改 HTTP 端口或改用 `file://`）也会改变存档来源；需要显式迁移，不能直接切换。
不得将 `com.frog.offline` 用户导向 `com.travelfrog.offline` 并称为无损升级。

构建前准备原有密钥，环境变量可设置 `FROG_SIGNING_KEY`（PKCS#8）与 `FROG_SIGNING_CERT`（PEM）；
未设置时使用 `dist/offline-signing-key.pk8` 与 `dist/offline-signing-cert.pem`。缺失时构建停止，不自动换密钥。
私钥、本机存档和构建日志不得新增到 Git 提交。

```powershell
python work/tools/patch_game.py
python work/tools/bundle_engine.py
node work/tools/engine_test.js
$env:FROG_UPGRADE_FROM = (Resolve-Path dist/TravelFrog-offline-3.3.apk).Path
python work/tools/build_release_apk.py
# -> dist/TravelFrog-offline-3.4.apk
python work/tools/apk_identity.py --apk dist/TravelFrog-offline-3.4.apk
adb install -r dist/TravelFrog-offline-3.4.apk
```

覆盖安装前备份存档，使用 `apksigner verify --print-certs` 比较新旧 APK 的证书 SHA-256，
使用 `aapt2 dump badging` 核对相同包名和递增版本号。安装后确认存档身份、库存和进度仍在。
也可运行 `python work/tools/verify_apk_upgrade.py OLD.apk NEW.apk`，签名、包名、版本或已知存储地址不符时退出码为 1；只传旧包则输出实包检测结果。
对外升级构建必须设置 `FROG_UPGRADE_FROM` 为实际发布的旧 APK 路径，构建脚本在发布产物前执行上述检查，失败不覆盖现有产物。此静态检查不能代替真机覆盖升级后的存档验收。
`build_release_apk.py` 从 `work/release.json` 读取发布身份和版本，校验新编译的 DEX 与存档桥、逐字节比对保留的资源及全部游戏资产，检查签名、资源对齐和递增版本；身份不符拒绝出包。原包必须与输出路径不同。
`android-apk/` 与 `build_android_apk.py` 保留为 `com.travelfrog.offline` 开发路线参考，不是当前正式发布入口。
`build_wrapper_apk.py` 是历史外壳构建工具，涉及额外的 Manifest/图标准备；正式发布统一使用上述 `build_release_apk.py` 流程。

已在 `com.travelfrog.offline` 游玩的玩家，其数据仍在该应用中。先确认旧版存档已导出，再到 3.4 的存档菜单导入；跨包自动迁移未实现。不要先卸载存档所在应用。

## 环境

| 需要 | 用途 |
|---|---|
| Node.js 18+ | 引擎单测、CDP 驱动、部分打包脚本 |
| Python 3.8+ | 数据解密、打包、验收脚本 |
| Edge 或 Chrome | `tools/cdp_drive.js` 等用无头浏览器驱动真页面 |
| 静态服务器 | 打开游戏页面（浏览器禁止 `file://` 读本地文件），`python -m http.server` 即可 |
| JDK 17 + Android SDK platform / build-tools | **仅**重新出 APK 时需要（`javac`、`android.jar`、`d8`、`zipalign`、`apksigner`、`aapt2`） |
| Windows + .NET Framework | **仅**编译 PC 启动器 `旅行青蛙.exe` 时需要（其余启动器跨平台） |

## 可移植性（换机器 / 换系统）

**脚本不写死任何绝对路径**：Python 脚本在文件头用
`PROJECT_ROOT = Path(__file__).resolve().parents[2]` 定位仓库根，Node 脚本用
`require('path').resolve(__dirname, '..', '..')`，PowerShell 用 `$PSScriptRoot`，
引擎本身用 `__dirname`。因此整个仓库搬到任何目录（Windows / Linux / macOS）都能直接跑。

需要外部工具链的脚本会在缺东西时**打印怎么指给它**，支持以下环境变量：

| 变量 | 作用 |
|---|---|
| `JAVA_HOME` / `FROG_JAVA_HOME` | JDK（`javac`、`java`） |
| `ANDROID_HOME` / `ANDROID_SDK_ROOT` | Android SDK 根；`build-tools/*` 与 `platforms/*/android.jar` 从它下面找 |
| `FROG_ANDROID_BUILD_TOOLS` | 直接指定含 `aapt2`/`d8`/`zipalign`/`apksigner.jar` 的目录 |
| `FROG_ANDROID_JAR` | 直接指定 `android.jar` |
| `FROG_BROWSER` | 无头浏览器可执行文件（默认按各系统常见位置与 PATH 查找 Edge/Chrome） |
| `FROG_CSC` | 编译 PC 启动器用的 `csc.exe`（非 Windows 不支持） |

也可以在仓库默认位置放工具链（这些目录不入库）：`work/jdk/`、`work/bt/android-*/`、`work/plat/*/android.jar`。

## 构建链

```powershell
# ① 重建"内联引擎"——改了引擎或数据表之后必须执行，否则页面里跑的还是旧代码
python work\tools\bundle_engine.py
#   产出 work/run/web/__offline-engine.js
#   它把 engine/index.js、protocol.js 与 gamedata/define/picture-layers/travel 四张表
#   一起内联，并注入 fs / process 桩。新增数据文件时记得同步它的内联清单，
#   否则 require 会在 try/catch 里静默降级。

# ② 若客户端资源缺失（首次 clone 或最小仓库），先从自有安装包重建
python work\tools\extract_game.py     # base.apk 的 assets/game/ -> work/run/web
python work\tools\patch_game.py       # 幂等离线补丁（从 main.min.js.clean 出发）

# ③ PC 解压即玩包
python work\tools\build_pc_exe.py     # 编译 C# 启动器（源码 work/app/pc/FrogLauncher.cs）
python work\tools\build_pc_zip.py     # -> dist/TravelFrog-PC.zip

# ④ 安卓发布包（先准备实际发布的旧包、原密钥与 SDK）
$env:FROG_UPGRADE_FROM = (Resolve-Path dist/TravelFrog-offline-3.3.apk).Path
python work\tools\build_release_apk.py
#   产出 dist/TravelFrog-offline-3.4.apk，已完成编译、对齐、签名和升级身份检查
python work\tools\apk_identity.py --apk dist/TravelFrog-offline-3.4.apk # 必须 RESULT: OK
```

### 安卓外壳

当前发布使用 `work/app/src/com/frog/offline/` 中的**干净外壳**，不包含国服渠道 SDK、推送、广告、
安全组件与原生库。它负责：

- `AssetServer`：把 `assets/game/**` 通过固定地址 `http://127.0.0.1:18763` 提供给 WebView（只读）；
- `MainActivity`：WebView 容器、系统文件选择器、`FrogNative` 导出/退出/存档镜像接口，以及兼容旧页面的 `SaveBridge`。

页面与 Java 的桥名、方法参数顺序和返回值必须一致；仅校验网页资产哈希不能证明原生桥可用。
原生存档镜像位于应用私有目录，不受 HTTP 端口分区影响，但**清应用数据或卸载仍会删除它**。玩家可保留的备份需通过导出写到应用外的文件。

> **不要**用 `tools/build_apk.py`：它会重新打包原始 APK，保留原 Application 类与渠道组件，
> 结果是装机后卡在渠道"登录中"界面。`tools/apk_identity.py` 专门检查这一点。

### 签名

必须使用官方 `zipalign` + `apksigner`（v1 + v2）。历史上自写的签名器漏写了 v2 签名块
尾部的 16 字节 magic，导致真机提示"安装包似乎无效（缺乏开发者证书）"。
后续版本**必须沿用同一把密钥**，否则 Android 会要求先卸载旧版（存档随之丢失）。

## 启动器的端口策略

浏览器按"地址"隔离 `localStorage`，端口一变就等于换了存档位置。四个启动器共用同一套策略：

1. 8080 空闲 → 使用它，并把端口记到 `last-port.txt`；
2. 8080 上已经是自己的服务 → 直接复用该地址，不另开服务；
3. 8080 被别的程序占用 → **停下来提示**（附 `netstat -ano | findstr :8080`），
   要换端口必须显式加 `--allow-other-port`（PowerShell 版为 `-AllowOtherPort`）；
4. 上次用过的端口仍空闲 → 沿用它。

验收：`python work/tools/test_port_policy.py`（11 项）与
`pwsh work/tools/test_launcher_port.ps1`（28 项）。
