## 二、旅行节奏（并入他的口径，全部可回退）

来源：他包里的引擎默认值（`FROG_MOTION_SEC`、`TRAVEL_MIN/MAX_SEC`、`TRAVEL_DEPART_CHANCE`、
`TRAVEL_WAIT_UNPREPARED_*`、`DRIFT_RETURN_*`、`STARTER_*`）。原来的值是我们自设的
「动作 45 秒、出门 12–40 分钟、没准备就不出门」。

| 项 | 3.6 默认（他的口径） | 环境变量回退到短节奏 |
|---|---|---|
| 在家动作间隔 | **10 分钟**（按 `Frogpattern` 顺序换） | `FROG_MOTION_SEC=45` |
| 一趟出门 | **120–510 分钟**，便当 HP 再放大，**硬上限 72 小时** | `FROG_TRAVEL_MIN=720 FROG_TRAVEL_MAX=2400` |
| 在家等待 + 掷骰 | 3–5 小时后掷一次，**50%** 才出门 | `FROG_WAIT_MIN/FROG_WAIT_MAX`（秒）、`FROG_TRAVEL_CHANCE` |
| 空背包出门（放浪） | 也能走，**10–20 分钟**（表值 10/20 是分钟，引擎存秒需 ×60） | `FROG_DRIFT_MIN/FROG_DRIFT_MAX` |
| 开局行李 | 便当各 3、护身符各 1（含 1 个四叶草）、工具各 1、特产各 2，只发一次（`preparationSeeded`） | 无开关（删掉该标记会再补一次） |

《「没准备就不出门」这条旧规则随之取消》：能不能出门改由掷骰决定，`tripPrepared()` 只影响
`waiting_for_bag` 提示。

## 三、礼物盒来访

- 出发时若礼物盒里有东西，**50%** 概率带走 1–3 件（`FROG_GIFTBOX_VISIT_CHANCE` / `_MAX_SEND`）；
  带走时推 `travel_load_gift`。
- 回来后由一位**旅行伙伴**寄「拜访回礼」：**50–300 三叶草**、35% 概率 1–2 张抽奖券、
  65% 概率一份礼物（草莓汁/苹果汁/任一种特产）、外加 **1–2 张该伙伴系列、优先未收集**的明信片。
  伙伴分池依据 `PictureTag.picNames` 里的 `_TRAVELER_ID` 标记（三类），不与他人的明信片混池。
- **顺带修掉两个真 bug**（3.4 上也存在）：
  1. `openMail()` 只发三叶草/券/扭蛋/物品，**邮件里的 `pictures` 会被静默吞掉**；
  2. `album_save_new` 只查 `albumPending`，探访来源的照片存在 `albumPendingVisit` 里，
     永远存不进相册（回 76 = 错误的新照片 id）。

## 四、家具工坊

- **心情/压力**：一个数值 `furniture.moodStress` 分档成客户端认识的 `Furniture.Mood`
  （0-2→1 很高兴 / 3-7→2 / 8-17→3 / 18-26→4 / ≥27→5 很生气）。压力来源：换一件摆放中的家具 **+1**；
  安抚：旅行回来 **−5**、手工品完成 **−3**、家具做成 **−2**。mood=5 时工作台"罢工"
  （客户端只在 `mood==Furniture.Mood.very_angry` 时画罢工图），并且**暂停新开工**（手动与自动两条路都挡）。
- **自动换家具**：每 8–12 小时检查一次，**35%** 概率把某件摆放中的家具换成同类型的另一件
  （已拥有的款式里挑），并推 `FurniturePut(22)`。
- **自动开工**：材料齐了但还没开工时，**35%** 概率自己开工。
- 两处与原作者口径的**差异**（如实标注，且都可用环境变量切回去）：
  1. 自动开工的检查间隔默认是"每拍"（外壳每 5 秒调一次 `tick`），照搬他的"每 3 小时"会让
     "放好材料半天不开工"看起来像坏了；`FROG_FURNITURE_AUTO_CRAFT_MIN_SEC=10800` 即恢复他的节奏；
  2. 摆好图纸+材料的**手动路径仍然立刻开工**（本仓库既有行为、玩家预期）。

## 五、其余三项

- **手工品阶段时长**：祈愿物 **86 分钟/阶段**、印章 **129 分钟/阶段**（他的口径；我们原先是自设的
  90 秒/阶段）。`FROG_CRAFT_WISH_STAGE_SEC=90` / `FROG_CRAFT_STAMP_STAGE_SEC=90` 可回退；木片仍是 270 秒。
- **客人回礼增强**：三叶草夹到 **50–300**；额外按"是否喜欢"两档概率发【特产 45/18 %、
  博物馆门票 28/8 %、花种 35/12 %】；**35%** 概率追加抽奖券（上限 `FRIEND_GIFTBOUNUS_TICKET_MAX`=3）。
  注意本仓库原先**没有**把 `ticket` 放进客人回礼邮件，这次一并补上。
- **旅行中寄明信片**：出发时就把这趟奖励掷好（`travel.rewards`），行程 **25%–75%** 之间把一张
  **还没收集过**的照片先寄回来（`deliverTravelPostcard` → `album_load_new`）；回家时不再重复发这几张。

## 六、明确**没有**采纳他的三处口径（会把 3.4 的既有修复/约定改回去）

| 他的口径 | 为什么不用 |
|---|---|
| 客人/访客 **8–10 小时**摇一次、停留 1 小时、冷却 0 | 3.4 是**故意**把客人调活的（60 秒摇一次、35%、停留 30 分钟、冷却 300 秒），他的节奏在离线版一个晚上可能一次都见不到客人。想照他的：`FROG_GUEST_ROLL=30000 FROG_GUEST_CHANCE=50 FROG_GUEST_COOL=0 FROG_GUEST_STAY=3600`（停留这次做成了 env） |
| `GUEST_FAREWELL_SEC = 20`（喂食后把剩余停留截成 20 秒） | 与 3.4 的明确修复冲突（"喂食不再把剩余来访时间截成 20 秒"） |
| `DRAWING_CHANCE = 20`（友情邀约） | 与 `docs/设计取舍与自定数值.md` 里写明"**用户指定** 75%"冲突。想照他的：`FROG_DRAWING_CHANCE=20` |

另外**没有跟着带过来**的，是他引擎里的两处缺陷：客户端会发 `animpicture_add_pic` 而他引擎没有
对应处理函数；以及自动开工时 `craftMaterialsFor(null)` 的空指针崩溃。


- **客户端可复现**：加上本 PR 的 12 处补丁后，`patch_game.py` 从 `main.min.js.clean` 生成的
  `work/run/web/js/main.min.js` 与本提交里那份**逐字节相同**（md5 `9e8da90af7`，1,328,396 B）。
- **三条测试改成数据驱动**：`craft` 的两条与 `layers` 那条原先写死了合并版（1088）数据的数值
  （候选最高 style=14、粗布 10005 不在配方里、点名 frogPose 的行必须都有青蛙层）。本仓库的表是
  1073 版，于是：候选最高 style 是 11、2001 的配方恰恰含 10005、`picture-layers.json` 里少 2076
  （hainan4）这一条记录。现在这些断言都**从本地表算**，并把"有 layer 记录却没画青蛙层（真 bug，
  必须为 0）"与"表里有、layers 文件没这条记录（数据版本差异，如实报数）"分开断言。
- **真机之外的一致性**：在另一条线的成品上核对过包内引擎与源码逐字节一致、PC 版载荷与安卓同一套
  （客户端/引擎 md5 相同、资源数相同），并用无头浏览器 + DevTools 协议确认存档能写进
  localStorage、二次启动能读回且开局行李不重复发。这些属于发布侧验证，不随本 PR 提交脚本。

## 八、依赖与限制

- 完整效果（新增资源、1088 版表）需要**官方 1088 增量**：本仓库按 CONTRIBUTING 不含资源，
  表数据也是随仓库自带；本分支的引擎对这些表是**防御式读取**的（表缺行时相关功能降级，不报错）。
- 本分支不解决真机验收：出门小时级节奏的体感、拜访回礼邮件的原生卡片、工作台罢工表现、
  旅行中弹新照片，都需要在设备上过一遍（见 `docs/测试与验收.md`）。
- 玩家说明书不在本仓库；我们这边的发布包说明见 `dist/说明书-V3.6.txt`（本 PR 不含成品与说明文件）。
