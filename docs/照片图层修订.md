# 旅行照片图层修订与验收

照片配置提供人物居中坐标和素材名，客户端将服务端返回的图层按顺序贴到 500×350 的画布。原离线生成器把人物放在底部中心，并在同一家族内选最小资源编号，可能把壁虎当成青蛙。现改为使用 PNG 注册框、Y 轴向上的配置坐标及明确的 QW/BH/CW/YHC 物种对应关系。

场景规则从早期照片导出工具移植。该工具的结果也有误，因此本轮另外修订：

- **1003 wet3**：伞面从旧导出的 `(170,95)` 调至 `(174,78)`，让伞顶位于内衬上方；单人和萤火虫合照共用同一规则。
- **107/108 竹林**：中景竹笋向后、向旁侧移动，解除它们与伙伴脚底重叠；左侧近景竹干向画外偏移。背景、人物、前景保持完整绘制顺序，不能将伙伴简单追加到所有前景之后。
- **202–204 垂丝海棠**：分开堆叠在左侧的花枝；人物与树桩本来就是一张组合素材，只绘制一次，并将树桩被裁切的底边接到画框底部。
- **206/207 风铃木**：移动遮住落脚树枝的前景花簇；206 的青蛙下移 16 像素以接近支撑枝条。前景花枝截断处安排在画框边缘。

这些摆位属于离线重建与人工修订，不是恢复出的官方服务端坐标。**2026-09-17，维护者已查看本地修订图片并确认通过验收。**201、205 等未找到充分修改依据的模板沿用参考导出的摆位，不宣称已修复所有赏花照片。

引擎直接返回完整、有序的图层。旧照片打开时重新附加图层，不更改相册编号，也不改存档内容。旧存档只记模板编号，无法恢复原始伙伴选择；游戏目前固定使用模板第一个有效伙伴组合，导出验收工具则覆盖全部组合及独照。

## 生成与验证

需要已提取的游戏资源、Pillow、numpy：

```sh
python work/tools/build_picture_layers.py
python work/tools/patch_game.py
python work/tools/bundle_engine.py
node work/tools/engine_test.js
```

客户端补丁让较矮天空素材撑满 350 像素，并把图层尺寸加入纹理缓存键；Python 导出使用相同尺寸。真实浏览器检查入口是 `work/probe/postcard_regression.js`，通过 `cdp_drive.js` 在独立存档运行。

导出本地验收册：

```sh
python work/tools/export_picture_review.py --output work/build/photo-review
# 指定旧导出目录时，保留原文件名、伙伴和随机背景，输出逐像素差异统计：
python work/tools/export_picture_review.py --output work/build/photo-review --reference-dir <旧照片导出目录>
```

打开输出的 `index.html`：左为旧图，右为修订图；可按编号搜索、仅显示重点模板或仅显示有变化图片。`after/` 保存原尺寸 PNG，`comparisons/` 保存重点逐张对照，`manifest.json` 保存素材、坐标、像素散列与变化数量。比较结果不能代替视觉验收。

与本地历史导出共 959 张相比，本轮摆位涉及 8 个模板、30 张照片。另外 3148/3168 的源 PNG 在两个项目中不同，当前项目是占位素材；这两项差异与图层修订无关。原素材仍缺少 8 个景点底图，生成器明确报告缺项，不用错图补齐。

验证结果：367 项引擎检查通过，浏览器存档、行李锁定及内容完整性检查通过。真实浏览器渲染 16 个模板，图层加载、500×350 画布、纹理缓存复用与尺寸变化均通过，未出现页面异常。浏览器导出的照片与 Python 合成逐像素比较，最大平均通道误差为 1.064/255 以内（插值及透明度混合差异）。图层身份和次序由回归测试约束，画面摆位以本次维护者验收为准。
